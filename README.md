# بوت تتبع المركبات GPSCJ

يعرض الموقع وبيانات الجهاز وسجل الحركة عبر تيليغرام، ويراقب مغادرة منطقة دائرية. التنفيذ الأساسي في `telegram_bot.py` وخدمات GPSCJ في `gps.py`. ملفات `telegram_bot_fixed*.py` أصبحت نقاط تشغيل توافقية تستخدم التنفيذ نفسه.

## التشغيل

يتطلب Python 3.10 أو أحدث؛ جرى الاختبار محلياً باستخدام Python 3.13.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

أنشئ `.env` بجانب `gps.py` بالاعتماد على `.env.example` إذا لم يكن موجوداً. إذا كان لديك الملف بالفعل، أضف الإعداد الناقص دون استبدال بياناتك:

```dotenv
ALLOWED_USER_IDS=123456789,987654321
```

استبدل الأرقام بمعرفات حسابات تيليغرام المسموح لها بعرض بيانات المركبة. هذه معرفات رقمية للحسابات، وليست أسماء المستخدمين أو أرقام الهواتف. يجب تعبئة `BOT_TOKEN` و`DEVICE_IMEI` و`DEVICE_PASSWORD` و`EMAIL` أيضاً. عند غياب قائمة الحسابات يبدأ البوت في وضع الإعداد، ويحجب بيانات المركبة. أرسل `/id` في محادثته الخاصة للحصول على معرّف حسابك، ثم أضفه إلى `ALLOWED_USER_IDS` وأعد تشغيل البوت. عرض البيانات متاح للحسابات المسموح بها في المحادثة الخاصة فقط. إرسال `/id` لا يمنح صلاحية الوصول تلقائياً.

```bash
.venv/bin/python telegram_bot.py
nohup .venv/bin/python3 telegram_bot.py

```

أرسل `/start` إلى البوت من حساب مسموح. لتشغيل تقرير GPSCJ من الطرفية:

```bash
.venv/bin/python gps.py
```

يُقرأ ملف `.env` من مجلد المشروع حتى عند التشغيل من مجلد آخر. التقارير والسجلات تحفظ افتراضياً في `gps_output1`، ويمكن تغيير الموقع عبر `GPS_OUTPUT_DIR`. تُدوّر السجلات عند 5 ميغابايت مع الاحتفاظ بثلاث نسخ سابقة. `.gitignore` يستثني بيانات الدخول وملفات التتبع المحلية.

## الإصلاحات

- تصحيح ترتيب خط الطول وخط العرض عند رسم العلامات والمسارات.
- إصلاح التنقل من الصور إلى النصوص، وتحديث رسالة التحميل نفسها، وتجاهل خطأ «الرسالة لم تتغير» فقط.
- جعل زر التحديث يعيد تحميل الخريطة أو سجل اليوم المختار بحسب العرض الحالي.
- فك استجابات JSON المتداخلة مع الحفاظ على محتوى النصوص، والتحقق من الإحداثيات والأرقام غير المحدودة.
- إظهار حالة الحركة المفقودة كغير متوفرة، ومعالجة القيم المنطقية والنصية لحالة التوقف.
- التمييز بين سجل حركة فارغ وفشل الخادم، وقبول الإحداثيات الصحيحة عند `(0, 0)`.
- إغلاق جلسات HTTP بعد الطلبات حتى عند الفشل، واستخدام مجلدات مؤقتة مستقلة للخرائط.
- تصحيح الإزاحة الزمنية السالبة مثل `-00:30`، والتحقق من إدخال الإحداثيات ونصف القطر، ومسح حالات الإدخال المتروكة.
- استمرار المراقبة بعد خطأ إرسال مؤقت، وإيقافها عند حظر البوت، وإلغاء مهام المراقبة عند إغلاق التطبيق.
- تقييد الوصول بالحسابات المحددة وإخفاء سجلات طلبات HTTP المعتادة التي قد تتضمن توكن تيليغرام.

## التحقق وحدود التشغيل

```bash
.venv/bin/python -m unittest discover -s tests -v
```

الاختبارات محلية وتستخدم محاكاة للشبكة وتوليد الخرائط واستدعاءات تيليغرام. لم يُشغّل البوت أو تُرسل رسائل فعلية أثناء الإصلاح. في 2026-09-07 جرى التحقق بقراءة مصادَق عليها من استجابة GetTracking الحية ومراجعة JavaScript العام للمنصة؛ لاحقاً صُحّح سجل الحركة ليتبع `GetDevicesHistory` كما تستخدمه واجهة `JS/Playback.js`، وتم التحقق من مسار البوت الفعلي باسترجاع 175 نقطة من سجل 2026-09-07. لا يثبت ذلك إتاحة السجل لكل الأيام أو الحسابات.

الخريطة لقطة للموقع عند الطلب، ويمكن تحديثها بالزر. تنبيه المنطقة يفحص كل دقيقة؛ يتكرر أثناء بقاء الجهاز خارجها. تعتمد النتيجة على آخر إحداثيات يعيدها الخادم، ولا توجد حالياً حماية خاصة من بيانات الموقع القديمة. إعدادات التنبيهات محفوظة في الذاكرة وتحتاج إعادة تفعيل بعد إعادة تشغيل البوت.

## ميزات مقترحة حسب الأولوية

1. **تنبيه انقطاع الجهاز وقِدم الموقع:** تمييز آخر موقع معروف عن موقع حديث، وإيقاف استنتاجات مغادرة المنطقة عند تقادم البيانات.
2. **حفظ الإعدادات في SQLite:** استعادة المناطق والتنبيهات بعد إعادة التشغيل، مع فترة تهدئة لتقليل تكرار الإشعارات.
3. **تنبيهات السرعة والبطارية:** حدود قابلة للضبط لكل مركبة، وإشعار عند العودة للحالة الطبيعية.
4. **تصدير الرحلات إلى CSV وGPX:** مشاركة المسار وتلخيص زمن الحركة والتوقف والمسافة التقريبية.
5. **دعم عدة مركبات:** اختيار الجهاز وتحديد صلاحيات المستخدم لكل مركبة.
6. **موقع مباشر متجدد:** تحديث رسالة موقع واحدة تلقائياً لفترة يختارها المستخدم، مع زر إيقاف واضح.

## دقة بيانات الحركة والاتصال والمسافة

يعتمد عرض الاتصال على `status` وفق واجهة GPSCJ؛ الحقل `ofl` مدة بالدقائق تُستخدم عندما تكون الحالة `Offline`، وليس رمزاً ثنائياً للاتصال. حالة التوقف ومدتها تصفان بيانات الخادم ولا تضمنان الحالة الفعلية الآن. وحدة `distance` هي المتر بحسب تأكيد المستخدم، ويعرضها البوت بالكيلومتر والمتر معاً، مثلاً `11.75 كم (11,747 م)`؛ مسافة السجل المحسوبة من الإحداثيات تبقى بالمتر والكيلومتر. انظر [نتيجة التحقق](VERIFICATION.md).

## إصلاح طلب سجل الحركة

يستخدم السجل `/Ajax/DevicesAjax.asmx/GetDevicesHistory` مع `DeviceID` و`Start` و`End` و`TimeZone` و`ShowLBS=2`. تتم متابعة الصفحات عبر `lastDeviceUtcDate` والتوقف عند انتهاء النتائج أو تكرار `lastLocationID`، مع إزالة نقاط التداخل. عند تعذر استكمال الصفحات لا يُعرض السجل الجزئي كأنه مكتمل. يظهر رفض الوصول وحد طلبات المنصة برسالة عربية محددة. نجحت 67 حالة اختبار بعد هذا الإصلاح.

### تنبيهات الكهرباء والاتصال

اختر «📡 تنبيهات الكهرباء والاتصال» ثم «تفعيل التنبيهين». يفحص البوت كل دقيقة:
- انقطاع الاتصال بحسب حالة الخادم `Offline` أو `LoggedOff`.
- انتقال مصدر الطاقة من خارجي (`1` أو `2` أو `3`) إلى داخلي (`0`)، بحسب تعريف البروتوكول الموجود في المشروع.

يحتاج تنبيه الكهرباء إلى رصد التغذية الخارجية أولًا. مصدر مجهول أو بيانات مفقودة،
انخفاض الجهد وحده، إطفاء المحرك، وقدم الموقع لا تؤكد انقطاع الكهرباء ولا تطلق التنبيه.
إذا انطفأ الجهاز دون إرسال تغيير مصدر الطاقة، يمكن اكتشاف انقطاع اتصاله فقط دون تأكيد السبب.

تتكرر رسالة الحالة وآخر موقع عند اكتشاف المشكلة كل 3 ثوانٍ حتى الإيقاف اليدوي،
مع احترام مهلة Telegram. التنبيهات مستقلة عن مراقبة المنطقة وتحتاج إعادة تفعيل بعد إعادة تشغيل البوت.

عند اكتشاف انقطاع الكهرباء أو الاتصال، يرسل البوت آخر موقع معروف كرسالة موقع مرة
واحدة، ثم يبدأ التنبيهات المتتالية. يحتفظ بآخر إحداثيات متاحة أثناء المراقبة إذا كانت
استجابة الانقطاع بلا موقع. إذا لم يتوفر موقع محفوظ يوضح ذلك قبل التنبيهات. هذا الحفظ
في الذاكرة ولا يستمر بعد إعادة تشغيل البوت.

مهلة اتصال HTTP هي 5 ثوانٍ ومهلة قراءة الاستجابة 15 ثانية. لا يعيد الطلب نفسه عند
أخطاء الاتصال أو القراءة؛ تستأنف المراقبة المحاولة في الفحص التالي. رسالة
`Network is unreachable` تتطلب استعادة اتصال الشبكة على جهاز تشغيل البوت، ولا تعني
بحد ذاتها انقطاع جهاز GPS. كذلك رسائل `Application is stopping` بعد Ctrl+C طبيعية.

### تنبيهات السرعة وجهد البطارية

من القائمة اختر «تنبيه تخطي السرعة» أو «تنبيه انخفاض جهد البطارية»، ثم «تحديد القيمة
وتفعيل التنبيه» وأرسل الحد المطلوب. السرعة بوحدة كم/ساعة (أكبر من 0 وحتى 300)،
والجهد بالفولت (أكبر من 0 وحتى 100). تقبل الأرقام العربية والكسور العشرية.

تنبيه السرعة يعمل عند تجاوز الحد، وتنبيه الجهد عند بلوغ الحد أو الانخفاض عنه.
يعتمد الجهد على `dataContext.voltage`؛ لا يمثل نسبة الشحن ولا يثبت نفاد البطارية
الداخلية. القراءات المفقودة أو غير الصالحة لا تطلق تنبيهًا. لكل تنبيه حد مستقل وزر
إيقاف مستقل، ويمكن تغيير القيمة وإعادة التفعيل. تُفحص البيانات كل دقيقة، ويُرسل
آخر موقع معروف أولًا ثم تتكرر التنبيهات كل 3 ثوانٍ حتى الإيقاف اليدوي، حتى لو زالت
الحالة. يجب إعادة التفعيل بعد إعادة تشغيل البوت.

### تصدير سجل الرحلات إلى CSV وGPX

افتح سجل الحركة واختر اليوم أو تاريخًا مخصصًا، ثم اضغط «تصدير CSV» أو «تصدير GPX».
يرسل البوت ملفًا باسم `trip_YYYY-MM-DD.csv` أو `trip_YYYY-MM-DD.gpx` إلى المحادثة
الخاصة المصرح بها. يتضمن التصدير نقاط اليوم كاملة بحسب سجل الخادم، دون تقسيم تلقائي
إلى رحلات منفصلة. يرتبط الزر بتاريخ عرضه ويجلب بيانات ذلك التاريخ مجددًا عند التصدير.
يبقى التصدير متاحًا إذا فشل رسم الخريطة بعد تحميل النقاط.

CSV بترميز UTF-8 مع BOM، وأعمدته `timestamp,latitude,longitude,speed_kmh`.
GPX يتبع بنية GPX 1.1: https://www.topografix.com/GPX/1/1/، ويحتوي نقاط المسار
والأوقات المتاحة، مع السرعة بوحدة كم/ساعة في وصف النقطة. يحتفظ التصدير بالمنطقة الزمنية
إن وردت ضمن الوقت ولا يفترض UTC عند غيابها. الأوقات غير الصالحة تُترك فارغة في CSV
وتُحذف من GPX؛ لا تُصدّر الإحداثيات غير الصالحة. تُجهّز الملفات في الذاكرة دون حفظها على القرص.

### موقع مباشر متجدد

اختر «📍 موقع مباشر متجدد» ثم «بدء المشاركة لمدة ساعة». يرسل البوت رسالة موقع
مباشر في تيليغرام ويفحص بيانات الجهاز كل 15 ثانية، ويعدل نفس الرسالة عندما تتغير
الإحداثيات. يعرض تأكيد البدء وقت آخر موقع مسجل عند بدء المشاركة؛ يعتمد تجدد الموقع
على البيانات التي يرسلها الجهاز إلى الخادم، ولا يثبت تشغيل المشاركة أن القراءة حديثة.

يمكن الإيقاف من زر الموقع أو من القائمة. المشاركة تنتهي بعد ساعة ولا تتكرر تلقائيًا.
عند فشل طلب البيانات يحتفظ البوت بآخر موقع ويحاول في الفحص التالي؛ لا يرسل إحداثيات
مفقودة. يتعامل مع مهلة Telegram ويوقف المهام عند الإغلاق الطبيعي. بعد انقطاع العملية
بشكل مفاجئ قد تبقى علامة المشاركة حتى انتهاء مدتها، وتحتاج بدء مشاركة جديدة بعد
إعادة التشغيل. لا يؤثر إيقافها على تنبيهات الجهاز الأخرى.
